# 学习台

## 第一次使用

1. **这台 Mac 已经编译好：** 在访达打开项目文件夹，双击根目录的 **学习台.app**；把它拖到程序坞，以后点图标即可。保留整个项目文件夹。其他 Mac 第一次使用时，在项目目录的终端执行一次 `bash app/macos/build.sh`；以后改课程或网页不用重新编译。
2. **停止：** 按 **⌘Q**，或点窗口左上角的关闭按钮。应用会先保存输入再关闭后台，不需要保留终端。若提示文字尚未安全保存，窗口会留下来供你处理。
3. **首次被 Mac 拦截：** 对已确认来源的“学习台.app”点右键 → **打开**，按系统提示处理。本机编译并临时签名的版本通常无需这一步；不要关闭系统的安全保护。
4. **更新课程：** 把 Claude 给的 `learning-hub-update-*.zip` 放进“下载”，不用解压。学习台 **设置 → 课程内容 → 检查更新**；核对版本和新增卡片，再点“更新”。完成后页面自动载入新内容。
5. **记录与问题：** 正式记录在 `progress/progress.json`，自动备份在 `progress/backups/`，未确认输入在 `progress/drafts/`。出错先看页面提示；菜单 **帮助 → 打开日志文件夹** 可找到日志。保留原项目和草稿，不用清空或重装。
6. **Windows：** 完整解压分享 ZIP，或克隆开发仓库到 `C:\Users\<你的用户名>\learning-hub`，按 [Windows 一步一步说明](WINDOWS_TEST.md) 安装桌面快捷方式。使用 Edge 独立窗口，关闭后后台会在一段时间后自动退出（无心跳 30 分钟；更及时的看护方式待在 Windows 上完成）；实测结果与人工确认项目见 [Windows 验收报告](WINDOWS_REPORT.md)。项目不要放进 OneDrive 同步目录。Windows 开发机通过 Git 同步课程，正式内容更新包在 Mac 应用。

默认外观是 **清透、深浅色跟随系统、黑体正文、标准字号、动效跟随系统**。本地学习不需要联网；只有主动打开的外部资源和视频使用网络。

## 每次怎样学

- **今天：** 查看推荐卡，点“开始学习”或“继续学习”。焦点不在输入框、按钮、链接等控件上时，也可以按 Enter。
- **路线：** 看整条线的顺序和当前位置。点击锁定卡可以查看先要学什么；“新”标签在你打开这张卡后消失。
- **学习卡：** “学”读讲解和资源 → “练”写自己的理解、对照答案、自己标记 → “结”完成。自己写回答是可选的，每道题标记为答对是必需的。一句话总结默认**可选**：写不出来时可以点“写不出来？看看这节的要点”，也可以一键把要点用作自己的总结再改几个字。想强制自己每张卡都写，在设置里打开“完成卡片时要求写总结”。
- **任务卡：** “任务”读导师消息和数据说明 → “动手”运行你自己的代码、提交答案 → “结”写总结。如果还有文字结论和自查要点，也要完成后再提交。
- 三个阶段可以自由切换。读到“学”的底部或点“下一步”后，“学”会有小对勾；它不会因为来回切换而取消。
- 资源的“标记为已完成”只帮助记住看到了哪里，不影响卡片的完成条件。已完成卡可以重新阅读、修改回答和总结，完成状态仍保留。
- 任务答错只告诉你需要再检查；完成任务，或**同一道题累计答错 3 次**后，才可查看参考解法。
- **课题组：** 按人物查看任务消息、自己的总结和导师回复。这个课题组是虚构的，回复来自课程内容，不会把你的文字发送给真实人物。
- **记录：** 在时间线、“我的笔记”和“回看”之间切换，按路线筛选。“回看”集中列出你标记为“还没答对”的自测题，以及答错 3 次以上、还没答对的任务题，点一下直接跳到那道题；改对后它会自己离开列表。点“导出学习记录”会复制摘要，并在 `progress/exports/` 保存 Markdown 文件。
- **第一次打开卡片：** 标题下方有一条说明“学 → 练 → 结”和常用快捷键的提示。点“知道了”或切换一次阶段后不再出现（记在 `progress/settings.json`，不影响学习记录）。

卡片中的“复制给 AI”只把文字放进剪贴板，由你决定粘贴到哪里。它不会自动发消息。任务标准答案和尚未解锁的参考解法不会被夹带进去。

## 输入怎么保存

自测回答、一句话总结和文字结论在停顿约 **500 毫秒**后自动保存。阶段与阅读位置每张卡最多每 **2 秒**写入一次，离开卡片或退出时补写；重新打开卡片会回到保存的阶段和位置。阅读位置是程序自己的记录，不算草稿：存不上会悄悄重试，仍失败就等下次打开重新记录，不会弹出“草稿等待确认”。

尚未得到服务器确认的输入会立刻尝试写到 `progress/drafts/`，同时留一份当前浏览器暂存。磁盘草稿按项目、窗口、卡片、字段分别保存，换端口或换浏览器也能找回。页面有“查看并恢复草稿”的提示。

**未确认保存的草稿没有过期时间，也不按数量自动删除。** 点击提示后逐条核对，再选择“恢复”或“丢弃”；丢弃需要再点一次确认。重新打开时不会自动把旧草稿覆盖到正式记录。已正式保存且后端核对一致的草稿可清除内容，仍保留序号以阻止迟到请求把旧文字重新写回来。其他窗口的草稿分别保留。

任务答案在点“检查答案”前只算草稿。恢复它只填回输入框，仍由你自己点检查。外观设置和写作输入也参与退出保护。Mac 退出时最多等待两秒尝试正式保存；未正式保存的文字只要已得到磁盘草稿确认，重新打开就会提示恢复。两处都没有确认保存时，应用会取消正常退出、保留窗口。

Windows 和备用浏览器窗口会在输入时持续写草稿。关掉前若出现“尚未写入磁盘”的提示，请保持窗口打开并重试，或先复制文字。强制结束程序或突然断电时，尚未发到服务端的输入无法由后台补写；页面不会把这种情况显示成“已保存”。

若出现“记录已在别处更新”，说明你正在写的这一处文字（某道题的回答、总结或文字结论）在另一个窗口里也被改过。程序会重新读取记录并保留当前草稿。核对草稿后恢复，或选择继续使用更新后的记录；不会悄悄用旧页面覆盖新记录。只是在别的窗口里阅读、翻页或勾选，不会引起这个提示。

## 学习记录、备份与恢复

| 文件或目录 | 用途 |
|---|---|
| `progress/progress.json` | 正式答案、自评、尝试、总结、完成状态和阅读位置 |
| `progress/settings.json` | 主题、深浅色、字体、字号、动效和侧栏偏好 |
| `progress/drafts/` | 未确认输入；只能经正式保存核对或你明确丢弃后清除，不自动过期 |
| `progress/backups/progress-时间.json` | 每次启动留下的学习记录原件备份，保留最近 20 份 |
| `progress/progress.corrupt-时间.json` | 检测到损坏时隔离保存的原件，不参与自动清理 |
| `progress/exports/` | 主动导出的学习记录摘要 |
| `backups/content-时间/` | 内容更新前的课程备份，和学习记录备份分开 |

每次写记录，程序先写同目录的临时文件，完整写入并刷新到磁盘后，才替换正式文件。不同标签页或进程保存时，要先核对当前文件的修订标识；旧版本请求会被拒绝。

**学习记录自动备份发生在每次启动时。** 新备份成功后才清理多余旧备份。若启动时不能安全备份，程序会暂停写入并提示原因。已经确认保存的数据仍在正式记录中。

发现正式文件损坏时，程序会保留损坏原件，从新到旧寻找可用备份，并提示用了哪份备份。备份之后的操作可能需要重新补回。没有可用备份时，程序保持只读，不生成空记录覆盖原件。

看到恢复或只读提示时：

1. 先保留页面中的未保存草稿，不清理磁盘草稿目录。
2. 记录页面和日志提示；暂时不要清理 `progress/`。
3. 请 Codex 协助检查损坏原件和备份，再通过程序恢复。不要自己编辑 JSON 内容。

### 记录格式升级

当前学习记录格式是 `spec_version: 2`。程序遇到 v1 时，先备份原始文件，再按 CONTENT_SPEC v0.5 升级：

- 增加 `pending_new_cards`，默认空列表。
- 每张卡增加 `ui.learn_completed`；已完成或已有自测／任务检查记录的卡设为 `true`，其余设为 `false`。
- 其他字段、未知字段、退休卡和所有历史尝试完整保留。

全部转换与校验成功后才保存升级结果。遇到更高版本时，程序拒绝写入，提示更新程序，不会降级。课程自己的 `content_version`、课程格式版本、学习记录格式版本与保存修订标识各有用途，不会相互替代。

## 收到内容更新包以后

日常使用设置里的“课程内容”。程序只检查“下载”文件夹顶层的更新 ZIP，在独立临时目录完整校验后，选择**内容版本最高**的新包；同一天的 `.10` 会排在 `.9` 后。先检查不代表同意更新，还要由你点击“更新”。包被改动，或课程版本在确认后被另一个更新器改变，都会拒绝本次应用并要求重新检查。

更新期间保存入口暂停，已接收的保存先完成。页面需要先正式保存当前输入；未检查的任务答案仍是草稿，请先处理后再更新。失败时显示原因：替换前被拒绝则原课程不变；实际替换后检查不通过则恢复备份。检查结果只写卡片和问题（例如“first-card：缺少有效的核实日期”），不含参考答案。

根目录的 **启动学习台.command** 和 **更新内容.command** 保留作备用，一般用不到。备用启动会打开浏览器；页面关闭后服务会在 30 分钟无心跳时退出，也可在对应终端按 Control+C。备用更新仍按修改时间选择 ZIP 并要求输入 y；也可在终端把“更新内容.command”和指定 ZIP 依次拖进去，中间留空格，再回车。不要同时运行多个更新入口。

更新器先检查全部路径与课程内部文件引用，再解压暂存、备份、整体替换，最后用程序自己读课程的代码把新课程完整读一遍。读不通会自动恢复七个获准路径；意外中断后，再运行更新器会先处理未完成操作。出现恢复失败或事务清单损坏时，保留 `backups/`，把提示交给 Codex。

更新范围只有：`content/`、`data/`、`docs/`、`tools/`、`HANDOFF.md`、`AGENTS.md`、`.agents/skills/learning-ui/`。工具不读取、不扫描、不替换 `progress/` 或 `workspace/`。不支持的课程格式也会在替换前拒绝，并提示先更新程序。程序和固定依赖仅供只读运行，不属于内容替换范围；WORKLOG 也不会被更新器修改。

内容备份保留工具自己创建的最近 **10 份完整备份**。过去由 Codex 手动应用更新包留下的旧备份没有自动清理标记，会保留。更新过程不写学习记录；刷新浏览器后，学习服务才正常更新“已见内容版本”和新卡标签。课程按永久卡片 id 对应记录，中间插卡、编号变化或退休卡不会删掉你的学习历史。

### 更新时怎样检查新课程

更新器**不运行更新包里的任何程序**。它用学习台自己读课程的代码（`app/server/content.py`，经 `app/updater/content_check.py`）把新课程完整读一遍：课程总表、每张卡的字段和章节、前置关系、任务数据文件和标准答案文件。读不通就不替换（检查阶段）或自动恢复备份（替换之后）。

包里的 `tools/validate_content.py` 仍会随更新一起复制，它是写课程的人自己用的、更严格的检查清单（例如字数、时长提醒），手动应用更新包时照常运行；它改了也不需要任何人复核，因为程序不会执行它。

## 外观、字体与快捷键

点侧栏底部的设置齿轮，可以实时切换纸页／清透、浅色／深色／跟随系统、黑体／宋体、标准／大字号，以及减弱动态效果。纸页使用暖色底与衬线大标题；清透使用白色或近黑底与系统无衬线大标题，两套布局和功能相同。

纸页保留指定的 Iowan Old Style / Songti SC 字体栈。2026-10-03 的预览验收已在这台 Mac 上确认两种字体能显示，并检查过 40px、56px 中英文混排；阶段二保留此字体栈并检查纸页截图，未重新做平台字形取证。没有更换或下载字体。

| 快捷键 | 操作 |
|---|---|
| ⌘K / Ctrl+K | 搜索卡片、页面和操作；上下键选择，Enter 执行 |
| G，再按 T / R / L / J | 今天 / 路线 / 课题组 / 记录 |
| ← / → | 卡片页切换阶段 |
| ⌘Enter / Ctrl+Enter | 对照自测答案或检查任务答案 |
| Y / N | 参考答案已展开时，标记答对／还没答对 |
| ⌘\ / Ctrl+\ | 展开／收起侧栏 |
| Esc | 关闭浮层 |
| ? | 查看快捷键一览 |

Mac 外壳另有 ⌘, 设置、⌘R 安全重新载入、⌘+ / ⌘− / ⌘0 缩放，以及标准的复制、粘贴和撤销菜单。Windows 页面按 Ctrl 显示提示并响应快捷键。

在输入框里打字时，单字母快捷键不会执行。界面内的“减弱动态效果”可以直接使用；开发和测试不会擅自改变 Mac 系统设置。

## 动效体验清单

先把学习台设置中的“减弱动态效果”设为“跟随系统”。如果 Mac 系统本来开启了减弱动态效果，下面的操作会直接显示结果，这是正常表现。是否更改系统开关由你决定。

正式程序中的答题、完成都会写入学习记录。集中验收在临时项目中做；只看设计演示也可以打开保留的 `app/preview/index.html`，它是 v2.2 设计参考，不写正式记录。

| 动效 | 在哪里、怎么触发 | 应该看到什么 |
|---|---|---|
| 今天首次入场 | 启动服务后第一次进入“今天” | 标题、主卡、其他区域依次淡入并略微上移；同一次启动再回今天不重复 |
| 页面切换 | 点击今天、路线、课题组、记录 | 旧页淡出，新页从下方一点的位置进入；不支持 View Transitions 的浏览器直接切换 |
| 标题连续过渡 | 从今天主卡或路线的可学节点进入卡片 | 卡片标题过渡到阅读页大标题位置，侧栏进入专注阅读布局 |
| 卡片悬停 | 鼠标移到主卡或其他推荐卡 | 边线变清楚、背景略变、轻微上移，没有循环或弹跳 |
| 按钮按下 | 按住一个可用按钮再松开 | 按钮短暂缩小，松开后恢复 |
| 阶段向前／向后 | 点“学 → 练 → 结”，再反向切回 | 内容随前后方向轻微横移，阶段高亮块移动到新位置；用 ←／→ 键切换时内容直接替换，只有高亮块移动 |
| 对照答案 | 学习卡的练阶段，点“对照答案”或按 ⌘Enter / Ctrl+Enter | 答案区域平顺展开，下方出现自评按钮 |
| 逐题推进 | 对照答案后点“我答对了”或“还没答对” | 当前题收成摘要，下一题展开并进入视野；最后一题后出现去总结入口 |
| 重看一题 | 点击已答题的摘要或左侧题目目录 | 对应题重新展开，原回答和标记保留；“全部展开”可以同时查看所有题 |
| 答错反馈 | 任务卡提交一个不正确的答案 | 题目下方淡入“不对，再检查一下”，记录尝试次数；输入框不抖动、不变红框 |
| 答对反馈 | 任务卡提交正确答案 | 对勾出现、边线变为正确状态，题目收成已答对摘要 |
| 提示逐条展开 | 任务卡的动手阶段，依次点提示 1、提示 2 | 当前提示展开，后一个入口按顺序可用 |
| 参考解法展开 | 同一道任务题累计答错三次，或完成任务后，点展开参考解法 | 锁定说明变成可展开入口，展开真实参考内容；查看行为会被记录 |
| 阅读进度 | 在较长的学阶段实际滚动 | 顶栏底边细线随位置增长，目录当前项同步变化；桌面侧栏持续覆盖窗口高度 |
| 浮层出现与关闭 | 设置或“卡住了”；Esc 关闭 | 浮层略微放大并淡入，背景遮罩出现；关闭后回到原入口焦点。⌘K 搜索每天用得多，直接出现、没有动画 |
| 完成整套反馈 | 满足完成条件后点“完成这张卡” | 按钮中的对勾画出，随后完成卡片出现，刚完成的路线节点填满、轻轻放大并荡开一圈细环，下一张入口出现；任务卡显示总结与导师回复，主体约 1.2 秒 |
| 完成数字变化 | 完成时观察完成卡片中的路线完成数 | 旧数字向上移出，新数字进入；数字宽度保持稳定 |
| 代码复制反馈 | 鼠标移到代码块右上角，点复制 | 复制成功后图标短暂变成对勾，随后恢复；失败时提供手动复制文字 |
| 减弱动态效果 | 设置 → 减弱动态效果 → 开启，再重复上述动作 | 页面、阶段、浮层和完成反馈直接显示结果；阅读进度仍反映位置 |

## 最希望你重点看的 8 个地方

1. **从零开始：** 第一次打开是否是清透欢迎页，从 A1 正常进入，没有测试完成记录或“仅预览”面板。
2. **保存是否让你放心：** 写回答、总结后切页，关掉再开；检查原文字、阶段和阅读位置。遇到草稿提示时，恢复操作是否清楚。
3. **三阶段节奏：** 目录、逐题推进、自由切换、完成条件和缺少项目的跳转，是否容易理解。
4. **真实任务：** 任务数据能在访达显示，正确／错误反馈明确，同一道题三次答错后的参考解法规则合理。
5. **完成后的联动：** 下一张解锁、今天推荐变化、路线节点更新，以及课题组中自己的总结和导师回复。
6. **两套外观与滚动：** 清透／纸页、浅／深色、大字号下文字是否舒服；长页中侧栏和分隔线是否始终满高。
7. **内容更新：** 下载 ZIP → 设置里检查并确认更新 → 自动载入，提示是否清楚；原来的答案和总结保留，新卡标签是否正确。
8. **日常回顾：** 笔记筛选、搜索、复制给 AI、导出学习记录，以及下面常见问题的说明是否够用。

## 常见问题

| 看到的情况 | 可以怎么做 |
|---|---|
| 原生窗口一直停在加载或提示启动失败 | 打开帮助菜单里的日志文件夹，保留提示和日志；确认整个项目仍在。不要反复新建空项目 |
| 页面说没有连接到学习台 | 先保留输入，重新打开应用。未确认草稿会提示恢复；不要清理浏览器数据或 progress/drafts |
| 8765–8775 都被占用 | 关闭不再使用的学习台窗口，稍后再打开；仍失败时把日志交给 Codex，不要随意结束其他程序 |
| 找不到 python3，或版本低于 3.9 | 打开“终端”，输入 `xcode-select --install` 并按回车，按系统提示安装；或者安装 Miniforge，打开终端执行 `conda activate learn` 后再启动。不会要求安装额外 Python 包 |
| 更新工具找不到 ZIP | 在访达打开“下载”，确认文件名仍是 `learning-hub-update-...zip`；也可以按上面的拖入方法指定包 |
| 更新提示路径不安全、缺文件或校验失败 | 保留完整提示和原 ZIP，交给 Claude／Codex 检查。不要自行修改包内文件 |
| 点“更新”后提示还有草稿等待确认 | 有未确认的草稿时不能更新课程，这是为了保护你的输入。点更新区里的“查看草稿”，逐条恢复或丢弃，再点“回到设置”继续更新 |
| 上次内容更新未完成 | 重新打开应用会先恢复，再加载课程；恢复仍失败就保留 `backups/` 和提示，请 Codex 检查 |
| 学习记录损坏、恢复或只读提示 | 保留草稿与整个记录目录，按“学习记录、备份与恢复”处理 |
| 外观设置无法读取 | 程序暂用清透默认外观，原设置文件保留；请 Codex 检查提示，不用清空学习记录 |
| 浏览器没有允许自动复制 | 选中弹出的文字，按 ⌘C。程序没有复制成功时不会说“已复制” |
| 视频不播放或外部资源打不开 | 点击“在新窗口打开”的资源链接；检查网络。YouTube 是否能打开还取决于你的网络环境 |

## 桌面版的结构、重新构建和分享

接手与复查请先看 [ARCHITECTURE.md](ARCHITECTURE.md)，本次验证结果见 [QA.md](QA.md)。Mac 外壳源码在 `app/macos/`，修改 Swift 后在项目目录执行 `bash app/macos/build.sh`。构建要求 macOS 13 或更新版本，产物适用于编译所在 Mac 的处理器架构；分享给另一种架构时请在目标 Mac 重新编译。

应用使用你提供的暖白底、渐变橙书本图标（2026-10-14）：[Mac 主图](assets/icons/orange/learning-hub-icon-macos-1024.png)，图标集与说明在 [icons/orange/](assets/icons/orange/README.md)。Mac 构建时把 `AppIcon.iconset` 原样交给系统 `iconutil` 打包，16、32 像素用的是专门加粗的版本，不再缩放。Windows 快捷方式使用 `assets/icons/orange/learning-hub.ico`；已有快捷方式请重新运行“安装学习台”更新图标。之前的台灯图标文件原样留在 `assets/icons/` 作为存档，不再使用。书本图形参考 Lucide book-open（ISC 许可，见 [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt)）。

分享给 Windows 使用者时，在项目目录运行：

```sh
python3 -B app/distribution/build_share.py --platform windows --name learning-hub-share-windows-2026-10-04.1.zip
```

生成的 ZIP 在 `app/distribution/dist/`。Windows 专用清单只包含课程与教学数据、网页与后端、Windows 启动文件、内容更新器、固定依赖及许可证、校验器和定稿 ICO；不读取或收录学习记录、草稿、workspace、日志、备份、Git 历史、截图、HANDOFF、开发文档、测试或 Mac 源码。图标原图存档也不放进 Windows 包。

解压后的 `learning-hub` 顶层有 **安装说明.txt** 和 **安装学习台.cmd**，双击即可阅读或安装。说明涵盖 Python 下载、保存位置、安全提示、课程更新及保留记录的程序升级。说明源文件为 [installation.txt](distribution/windows/installation.txt)；打包时转为带 BOM 的 UTF-8 和 Windows 换行，安装入口转为 ASCII 与 Windows 换行。入口只运行现有安装脚本，不更改长期 PowerShell 策略。

对外分享时从最新已提交的 `main` 检出到新的临时目录后打包，避免纳入本地临时文件。对比课程版本、ICO 指纹与包内完整清单，并用解压后的程序做隔离验收。分享 ZIP 仅保存在本地，不会自动上传或公开；接收者不用安装 Git 或 Codex。通用开发分享模式仍可用 `--platform all`，其中包含内部交接文档，不能作为此 Windows 安装包交给学习者。
